# Two-core blinky Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The M4 toggles orange LD7 every 500 ms and the A7 toggles blue LD8 every 1000 ms from a systemd-started `dontfall-app`, and the OpenAMP hello keeps working.

**Architecture:** The M4 firmware gains a periodic `k_timer` that toggles the Zephyr `led0` alias (PH7). `dontfall-app` gains an opt-in `--led <dir>` mode: it takes over a Linux LED-class LED, does the existing hello once, then toggles `brightness` until SIGTERM, and on exit restores the original trigger. `meta-df` ships and enables `dontfall-app.service`, which runs that mode on `/sys/class/leds/heartbeat`.

**Tech Stack:** Zephyr (GPIO API, `k_timer`), C++17 + POSIX (sysfs, `clock_nanosleep`, `sigaction`), CMake/CTest with Python host tests, Yocto scarthgap (`systemd` class, `externalsrc`).

**Spec:** `docs/superpowers/specs/2026-10-12-blinky-design.md` (DontFall repo). Read it first.

## Global Constraints

- Repos: M4 = `~/Projects/DontFall-M4-ws/DontFall-M4`, app = `~/Projects/DontFall-app`, integration = `~/Projects/DontFall`. Read `VISION.md` and each repo's `AGENTS.md`.
- Commit messages: plain, **no** "Generated with", **no** `Co-Authored-By` trailers or any AI attribution. Commit per task, in the repo that task touches.
- Do not push. Do not bump `SRCREV` / `SRCREV_dfm4`.
- Never touch `SIGN_*`, keys, TF-A/FIP, or devicetrees. None of them need changing.
- Only one bitbake at a time on `build-stm32mp157c-dk2`. Run bitbake as `./build.sh bitbake ... </dev/null`.
- Intervals: M4 500 ms, A7 1000 ms, both as the time between toggles.
- Linux LED dir: `/sys/class/leds/heartbeat`. Zephyr LED: `DT_ALIAS(led0)` (PH7, already defined by the board).
- Don't add or remove unrelated comments; match the surrounding code style (tabs in Zephyr C, 4 spaces in the app's C++).

## Review Focus

1. **Existing one-shot behaviour must not change.** `dontfall-app [device]` without `--led` still exits 0/1/2 as today: the existing `tests/test_rpmsg_hello.py` stays green and unmodified.
2. **The hello fails in blink mode** (M4 down, no `/dev/ttyRPMSG0`): the app must keep blinking, not exit. Covered by `test_blink_without_m4` (Task 2).
3. **`systemctl stop` leaves the board as it found it:** LED off, trigger back to `heartbeat`, exit 0, promptly (well under 1 s, not after the next tick). Covered by `test_blink_without_m4` (Task 2).
4. **Bad LED path:** a typo'd `--led` dir must fail loudly (exit 1, message naming the file) rather than "blink" nothing. Covered by `test_led_missing` (Task 2).
5. **Boot ordering:** `/dev/ttyRPMSG0` appears a moment *after* `dontfall-m4.service` finishes, and `/usr/local` is a separate mount. The unit has to wait for both, or the hello races at boot. Covered by the unit's `After=`/`RequiresMountsFor=` (Task 3) and the reboot check (Task 4).

### Task 2: `dontfall-app --led <dir>` blink mode

Repo: `~/Projects/DontFall-app`

**Files:**
- Modify: `src/main.cpp`
- Create: `tests/test_blink.py`
- Modify: `CMakeLists.txt` (register the new test)
- Modify: `README.md` (one short "Blink mode" paragraph: usage and that the service runs it)

**Interfaces:**
- CLI: `dontfall-app [--led <led-dir>] [device]`. `device` defaults to `/dev/ttyRPMSG0` as today. Unknown options → print `usage: dontfall-app [--led <led-dir>] [device]` to stderr, exit 1.
- Produces (used by Task 3): `dontfall-app --led /sys/class/leds/heartbeat` runs forever, toggling every 1000 ms; SIGTERM → LED off, trigger restored, exit 0.

Behaviour with `--led DIR`, in this order:
1. Read `DIR/trigger`. The current trigger is the word in `[...]` (sysfs format, e.g. `none [heartbeat] timer`). If there are no brackets, it's the whole trimmed content. On read failure: `cannot read DIR/trigger: <strerror>` to stderr, exit 1.
2. Write `none` to `DIR/trigger`. On failure: `cannot write DIR/trigger: <strerror>`, exit 1.
3. Run the existing hello (same messages as today). Failure is **not** fatal in this mode: the messages still go to stderr, then continue. Then `std::fflush(stdout)`: under systemd, stdout is a pipe to journald and fully buffered, so without the flush the M4's reply never reaches the journal while the app keeps running.
4. SIGTERM and SIGINT handlers are installed with `sigaction` **without** `SA_RESTART` **before step 2**, so a stop during the hello still restores the LED. The handler only sets a `volatile sig_atomic_t` flag; the hello's existing EINTR retries mean a stop during the hello just ends the loop below before its first toggle.
5. Loop: write `1`/`0` alternately to `DIR/brightness` (start with `1`), then sleep until `next += 1000 ms` with `clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, ...)`. When it returns `EINTR` (as its return value: `clock_nanosleep` doesn't set `errno`), re-check the flag. Exit the loop as soon as the flag is set.
6. On exit: write `0` to `brightness`, write the saved trigger back to `trigger`, return 0.

Write files with a truncating open (e.g. `std::ofstream`): sysfs ignores truncation, and on the regular files the tests use it makes the content exactly `1`/`0`. Keep the hello code path as-is: factor it into `int say_hello(const char *dev)` returning today's exit codes, which `main` returns directly in one-shot mode.

- [ ] **Step 1: Write the failing tests** in `tests/test_blink.py`, in the same plain style as `test_rpmsg_hello.py` (no pytest; `__main__` runs every test, prints `PASS`/`FAIL`, exits 1 on any failure; usage `test_blink.py <path-to-dontfall-app>`). Each test makes its LED dir with `tempfile.TemporaryDirectory()` containing `trigger` = `"none [heartbeat] timer\n"` and `brightness` = `"0\n"`. Always kill the child in `finally`.

```python
def test_blink_without_m4():
    # hello fails (no device) but blinking goes on; SIGTERM restores the LED
    proc = start(["--led", led, "/nonexistent/tty"])
    seen = sample_brightness(led, seconds=2.5, every=0.05)
    assert proc.poll() is None, "app exited instead of blinking"
    assert read(led, "trigger") == "none", "trigger not taken over"
    assert {"0", "1"} <= seen, f"brightness values seen {seen}"
    t = time.monotonic(); proc.send_signal(signal.SIGTERM)
    out, err = proc.communicate(timeout=2)
    assert proc.returncode == 0, f"exit {proc.returncode}, stderr {err!r}"
    assert time.monotonic() - t < 0.5, "SIGTERM waited for the next tick"
    assert read(led, "brightness") == "0"
    assert read(led, "trigger") == "heartbeat"
    assert "cannot open /nonexistent/tty" in err

def test_blink_with_hello():
    # pty plays the M4 as in test_rpmsg_hello.py
    master, slave = pty.openpty()
    proc = start(["--led", led, os.ttyname(slave)])
    assert read_line(master, 3) == b"hello from A7\n"
    os.write(master, b"hello from M4: hello from A7\n")
    time.sleep(1.5)
    assert proc.poll() is None, "app exited after the hello"
    proc.send_signal(signal.SIGTERM)
    out, err = proc.communicate(timeout=2)
    assert proc.returncode == 0, f"exit {proc.returncode}, stderr {err!r}"
    assert "hello from M4: hello from A7" in out, f"stdout {out!r}"

def test_led_missing():
    proc = start(["--led", "/nonexistent/led", "/nonexistent/tty"])
    out, err = proc.communicate(timeout=5)
    assert proc.returncode == 1
    assert "cannot read /nonexistent/led/trigger" in err
```

Copy `read_line` from `test_rpmsg_hello.py`. `read(dir, name)` returns the stripped file content. `sample_brightness` returns the set of stripped `brightness` values read every `every` seconds for `seconds`. Start the child with `stdout=PIPE, stderr=PIPE, text=True`.

```ini
[Unit]
Description=DontFall A7 application (OpenAMP hello + LD8 blinky)
Wants=dev-ttyRPMSG0.device
After=dontfall-m4.service dev-ttyRPMSG0.device
RequiresMountsFor=/usr/local

[Service]
ExecStart=/usr/local/bin/dontfall-app --led /sys/class/leds/heartbeat
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

`Wants`, not `Requires`: the blink must run even if the M4 never comes up. `RequiresMountsFor`: the binary lives on the userfs partition.
